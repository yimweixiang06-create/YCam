## 二、上传视频里的可靠视觉观察

用户录屏同一樱花场景：先进入色调/颜色/强度二维调色，再连续移动控制点。朝右侧高颜色方向滑动时，樱花粉色及天空蓝色同时明显增强，向左时呈低饱和/较灰的场景。

从录屏 *画面固定取样窗口*（x=38..464，y=165..759；屏幕截图像素、8 位 HSV 色度 0..255）得到：

| 视频时间点 | 平均 HSV S | 平均 RGB | 备注 |
| --- | ---: | --- | --- |
| 13s | 约 48 | 129/120/127 | 偏淡/偏灰方向 |
| 16s | 约 115 | 135/105/124 | 明显更鲜艳 |
| 20s | 约 121 | 137/105/128 | 继续偏高颜色 |

注意：场景存在轻微移动、手机 UI 遮挡、HDR/录屏/社交页面压缩，三个时点也不是严格相同 RAW 原始图。因此 **HSV S 增加约 73（13→20s）只支持“右侧颜色响应应明显”的方向性验证**；不能用作逐像素苹果准确度误差，也不能据此反求一个官方 LUT。左上/右上/左下/右下的明暗与灰白方向符合用户提供的模板，但仍缺同场景的官方色彩真值。

## 三、最近一次实拍候选审计（有时间限制，不冒称实时）

- 累积可追踪且去重的候选数 **1,600**；严格摄影证据 **477**，离 2,000 最低要求 **1,523**。
- 最后一轮 200 张中 **141** 张有相机 EXIF 证据、**7** 张有 Commons 摄影类别证据、**52** 张仅为未经证实的高分辨率 JPEG 候选。
- 最新审计确认官方同场景原图/效果配对数为 **0**；`readiness.json` 指示 `automatic_color_fit_permitted=false`。
- 28 种风格和 10 个传统滤镜每项被分配 42–43 个候选**测试目标**。脚本轮流指定的 `tested_effect` 不是下载照片实际的 `real_source_effect`。
- 最近一轮滤镜 `filter:vivid` / `filter:vividWarm` 的输出临近裁切比例分别平均约 0.155 / 0.135（仅每组五张不同图片）。**绝不能据此声称比原图或其他滤镜裁切更多**；这种不等输入的横向对比无效。
- 为修正这一问题，`tools/continuous_photo_check.py` 现在对每张照片记录 `input_near_clipping_fraction`、`near_clipping_fraction` 和 `clipping_change_vs_same_input`，并在 `quality_review.json/md` 标记 *有摄影证据且比其自身原图多 ≥8% 临近裁切* 的样本。该算法仍是 YCam Python 近似管线的审核，不等于真实 iPhone Core Image 截图或苹果准确度。

## 四、与苹果 iOS 27 的可确认差异

| 项目 | Apple 官方公开的行为 | 当前 YCam 状态 | 差异与后续验证 |
| --- | --- | --- | --- |
| 风格预览 | 相机的 Styles 可左右滑选择、Customize 调整 | v1.7 是独立圆形图标、文字与连续点阵；无照片缩放卡片 | 需通过实机 UI 截图逐项对比，不能宣称完全像素一致 |
| 强度/色调/颜色 | 支持二维 Tone、Color 与强度；不同机型控制略不同 | 上下明暗、左右纯度；多点调色盘自己生成背景 | 四角方向已可响应，但绝对强度尚无同场景官方真值 |
| 风格处理 | 苹果官方表示根据人物、皮肤、天空等分割掩膜选择性调整 | YCam 摄影风格主要是 Core Image LUT 与全局色调曲线；人物分割主要用于人像景深 | 需要肤色/天空局部保护与高光滚降测试，不得用全画粉色叠加冒充 |
| 拍后风格编辑 | 符合机型、格式要求时可在 Apple Photos 中调整 | YCam 输出的是自身已渲染图；尚无与 iOS Photos 原生风格兼容的可逆调整 | 需保存源数据与独立元数据、开发 YCam 自身再编辑流程；不保证 Photos 识别 |
| 质感、颗粒 | 部分支持 iOS 27 的新机型有 Texture/Grain | YCam 有部分 LUT/颗粒处理，但没有相同的 Apple 私有 Texture 管线 | 不复制不可验证的苹果内部质感模型 |
| 传统滤镜 | 苹果另有 Vivid/Dramatic/Mono 等 Filter | YCam 另有 10 种滤镜（与 28 风格分开） | 传统 Filter 参考不能误用成 Photographic Style 官方配对 |

## 五、下一步及不允许越过的门槛

1. 保持现有 YCam 界面布局、快门、名称、点阵、原黄色 11 档条、横向切换不变。
2. 继续每 5 分钟尝试收集最多 200 张已授权、唯一、可审核候选；按真实工作流结果报告，不保证 GitHub `schedule` 每 5 分钟一定触发。
3. 先监控同源输入图的色域/裁切与场景多样性，定位真正值得检查的风格；避免对不同输入做不公平的滤镜排名。
4. 严格摄影证据 ≥2,000 **且**每一目标风格有经验证的同场景原图/目标图、二维控制坐标、可信来源与独立 holdout 后，才自动拟合 Swift/LUT 并要求实测改善及 Xcode 构建后发布 IPA。
5. 不能把在线视频“播放前后的两个画面”称作严格配对 RAW/目标素材；也不能凭 2021 Apple 分割研究就声称实现了苹果 iOS 27 当前私有 ISP。

本次更新内容为研究记录及数据质量检查；**没有修改 YCam 摄影风格 / 滤镜的真实 Swift 系数或 LUT，也没有触发新的 IPA 发行**。
