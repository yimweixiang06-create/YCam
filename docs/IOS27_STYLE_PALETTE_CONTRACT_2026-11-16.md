# YCam：iOS 27 摄影风格与调色盘要求（2026-11-16）

> 用户提供的视觉/行为模板，作为后续差异对照与设计约束；不是 Apple 发布的官方 LUT 或像素真值。严禁仅根据描述拟合「官方色彩」或宣称已通过真实 ΔE 校准。

## 所有风格通用二维坐标

- 上 = 色调更亮、抬中高光、保护暗部细节；下 = 压暗、加强阴影层次，禁止黑位大面积糊死
- 左 = 降低色彩纯度/饱和度；右 = 提高纯度，同时保护肤色和高光免于裁剪
- 左上 = 明亮淡彩；右上 = 明亮鲜彩；右下 = 暗调浓彩；左下 = 暗调低饱和
- 中心 = 色调0、颜色0；底部 0...100 = 强度；强度0应完全去除当前风格（如另叠了传统滤镜，滤镜是否消失按独立滤镜设置决定）
- 每个二维点均需完整输出RGB转换，不得将一个坐标取样的颜色统一填充整个画面
- 控件外观必须保留：同一块磨砂玻璃面板、面板内三组数值、白色11×11点阵、原白色控制点、黄色11档强度滑条、原快门与模式位置
- 预览卡每项都使用**同一张当前相机实拍帧**，分别用真实 YCam 效果处理，使变更可比较。不是苹果官方原图配对样本。

## 用户指定的七种基础模板

| 模板 | YCam 现有最接近样式（非官方等价） | 定义和角落方向 |
| --- | --- | --- |
| 标准 Standard / Neutral 基准 | `standard`（注意与现有的 `neutral` 另一风格不同） | 不附加染色、忠实原图；↑明亮原色、↓真实暗调、←低纯中性、→原色更浓；左上白开水直出、右上鲜明直出、右下浓郁原色、左下克制灰暗 |
| 鲜明 Vibrant | `vibrant` | 保留原本色相与白平衡、色彩鲜活；↑明亮鲜活、↓浓郁暗鲜、←奶油鲜色、→强纯度；左上奶油、右上清亮高彩、右下暗调浓彩、左下柔暗鲜色 |
| 温馨 Warm | `warm` | 暖橙黄但保留肤色层次；↑午后轻暖、↓琥珀暗调、←低饱和奶油暖、→橙金更浓；左上暖白、右上明亮橙金、右下浓深暖棕、左下暮色暖灰 |
| 金色 Gold | `gold` | 高光暖金、阴影暖棕；↑通透金光、↓暗金厚重、←奶油香槟金、→浓郁金色；左上柔焦暖白、右上鲜明金色、右下深金电影感、左下复古棕灰 |
| 反差 Rich Contrast | 现有 `dramatic` 最接近，**不是完整 Rich Contrast 实现** | 高对比、暗部深、整体倾向低饱和；↑柔和反差、↓戏剧深阴影、←去色胶片、→较高纯度；左上柔灰、右上明彩反差、右下戏剧暗色、左下阴郁胶片 |
| 缥缈 Ethereal | 现有 `ethereal`（名称显示「空灵」） | 柔和、低对比、梦幻氛围；↑白雾感、↓柔暗色、←淡彩雾、→彩色柔光；左上仙气白雾、右上糖果柔色、右下深色柔光、左下灰雾 |
| 黑白对比 Noir | 现有 `monochrome`（也有传统滤镜 `noir`），**不是专有 Noir 复制** | 无彩色染色，只保留灰阶；↑银灰、↓硬黑白、←平滑中间调、→硬黑白；左上柔银盐、右上高调硬黑白、右下深黑高反差、左下柔暗灰 |

## 校准门槛

- 真实来源、许可、可核实实拍证据的照片跨批次去重达到 2000 之前，不开始据此拟合/发布「校准滤镜」。
- 普通无配对照片只能分析色域、曝光、肤色、灰阶与削波；不能假称每张是苹果/富士/柯达官方效果。
- 真实颜色准确度必须有同场景原片和目标效果片、风格 ID、色调、颜色、强度、二维坐标、截图哈希和独立 holdout；没有则不修改真实 Swift/LUT 配方。
- iOS 27 系统相机是专有 Apple 实现。YCam 可以对齐可见交互和公开特征，但不声称私有像素算法一模一样。
